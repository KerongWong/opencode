**Route chosen: fetch-time floor (merge level), not `session.created` invalidation.** The required regression is merge-level — `mergeRootSessionIndex([], [session("new", { time: { created: 2, updated: 2 } })], { includeArchived: false, boundedKnown: true })` must keep `new` — and only a merge-level change can make that call return a row; an invalidation-only fix leaves it returning `[]` and would have to weaken the required case. The merge route also recovers without a network round trip, and `dataUpdatedAt` is read from the query result that already exists, so no new request, query key or cache entry is introduced.

**Default when no fetch time is supplied.** The required call passes no `fetchedAt`, so the option is optional and an empty page with no fetch time applies no time bound (the known roots join, subject to the unchanged archived/child filter). That is the contract the required regression pins. The bounded Projects view always supplies the time, and a case pins the empty-page drop with an explicit `fetchedAt`, so truth 13 stays observable at the same boundary.

**Accepted limitation (stated, not hidden).** `time.updated` is a server timestamp and `dataUpdatedAt` is the client's wall clock. For the local sidecar the phase targets they share a clock; on a remote server whose clock is behind, a post-fetch creation can still be dropped, and if it is ahead an old known root can join an empty page. No new clock source or server API is added in this phase; the failure is a row-set difference that a remount or reconnect re-derives.
