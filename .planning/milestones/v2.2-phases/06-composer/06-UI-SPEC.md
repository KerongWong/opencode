# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> 本阶段是**渲染层缩短**：composer chip 与已发消息 file mention 的显示文本从全路径变为 basename（作用域内同名时最短区分后缀），hover `title` 保留全路径。正文与 wire 层永远写全路径。样式、布局、交互行为零新增。

## Typography

本阶段**不引入任何新字号/字重**。两处触点沿用各自容器现有排版：

| Role | Size | Weight | Line Height | 适用面 |
|------|------|--------|-------------|--------|
| Body（composer 正文） | 继承编辑器现有正文尺寸（不改） | 继承 | 继承（编辑器行高不动） | composer chip 的显示文本（basename / 区分后缀） |
| Label（用户消息 mention） | 13px（沿用气泡现有正文） | 440（沿用 `message-part.css` 既有值） | `--line-height-compact` = 16px | 已发消息 `data-highlight="file"` segment 的显示文本 |

规则（继承自 packages/app 与 packages/session-ui AGENTS.md，**不得违反**）：
- 不使用 `leading-none` / `line-height: 1`；13px 文本行高必须 16px。
- 不写字面字体族；显示文本是 prose（用户路径显示为普通文本，不是 code 字体——与现状一致，现状 message 侧 mention 即 UI font）。
- 双轨保留：`part.content` / 正文切片仍是**全路径**（wire 事实层），显示文本只在渲染节点上替换。

## 元素级显示契约（执行层真相，本阶段核心）

> 以下条目是 planner/executor 的视觉与交互真源，逐条对应 MENT-01/MENT-02 成功判据。

### E1 — Composer mention chip（MENT-01）

- **位置**：`packages/app/src/composer/editor/editor.tsx` `renderComposerEditor()` 内 `part.type === "file"` 的 span（约 570-605 行）。
- **显示文本**：`mention.textContent` 从 `part.content`（全路径）改为 **basename**；同一 draft 内存在同名 basename 的 file mention 时，改为 **最短区分后缀**（从尾部取 n 个路径段，直到不与作用域内同名 peer 共享；跳过空后缀——对齐 dsh `distinguishingPathSuffixes()` 语义）。
- **basename 提取**：`path.split(/[\\/]/).filter(Boolean).at(-1)`（`\` 与 `/` 均视为分隔符）。
- **`title` 属性**：`mention.title = part.path`（完整原始路径，**不含 `@` 前缀**）。现状 file 类无 `title`，这是唯一新增属性。
- **不变量**：`part.content`、`data-path`、`data-mime`、`data-filename` 全部保持全路径原值；`contentEditable="false"`、`dir="auto"`、`unicode-bidi: isolate` 不动；chip 点击/删除/编辑行为不变；`type: "session"` mention 不触碰。
- **作用域**：整个 draft 的所有 `type === "file"` parts（CONTEXT 锁定）。

### E2 — 已发消息 file reference（MENT-02）

- **位置**：`packages/session-ui/src/message/message-content.tsx` `CurrentHighlightedText()` 内 `data-highlight="file"` segment（约 822-884 行）。
- **显示文本**：`segment.text.slice(1)`（正文切片去 `@` 前缀后的全路径）替换为 E1 同算法的 **basename / 最短区分后缀**；`@` 前缀 span（`data-slot="user-message-mention-prefix"`）原样保留。
- **`title` 属性**：file segment 的外层 span（`data-highlight="file"`）加 `title`，值为该 mention 对应的**原始完整路径**（从 `props.files` 中按 mention `{start,end}` 匹配得到的全路径，不是正文切片——正文切片即全路径事实层，二者相等，但取数应来自 attachment 的 path 字段以保证单一真相）。
- **样式**：`[data-highlight="file"]` 既有 accent 色 + weight 440 + `direction: ltr; unicode-bidi: isolate` 全部保留（`message-part.css:192-198`）；不加新 class、不做 chip 卡片化。
- **不变量**：`props.text`（正文）不改；segment 切分逻辑（按 `files[].mention {start,end}` + `agents[].mention`）不改；copy 路径（`sessionReferenceClipboardText`）复制的是正文/附件真相，显示替换不影响剪贴板文本；`type: "agent"` segment 不动。
- **作用域**：该消息的 `files[]`（CONTEXT 锁定）。

### E3 — 消歧纯函数（单实现，双端复用）

- **位置**：新建于 `packages/session-ui`（如 `src/message/mention-label.ts`），App composer import 复用（app 已依赖 session-ui）。
- **签名**：输入作用域内 `{ path: string }[]`，输出 `Map<path, label>`（或同名等价签名，实现阶段定）。
- **算法**：移植 dsh `path-suffix.ts` 段窗口语义（只读参照，不整文件搬移）。
- **纯函数单测**：跟随 session-ui 包测试惯例；覆盖：无冲突（纯 basename）、两同名不同目录（最短后缀）、三同名链式、单段路径、尾分隔符、双分隔符混用、Windows 大小写（归一不做大小写折叠——按现状原样比较）。

### E4 — 正交不变量（验收锚点）

- composer `model.ts` 写入与 `request.ts` 序列化仍发/存**全路径**（本阶段零改动，作为回归断言而非改动项）。
- TUI 等其他端打开同一会话看到全路径，行为不变（MENT 成功判据 4）。
- 宿主文件 diff 控制在几行内（上游接缝预算：优先只增不改；触点 = editor.tsx 数行 + message-content.tsx 数行 + 新纯函数文件 + 单测）。
