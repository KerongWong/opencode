<objective>
让分组在 worktree 清单到达前就用项目已有的 `sandboxes` 兜底，使「同一 git 根的每一份本地 checkout 恰好一行」在首帧与清单到达后都是同一个答案。

Purpose: CHK-02、CHK-03、CHK-04。`normalizeProjectInfo` 只把 canonical 放进 `worktrees`（`runtime/server/global-sync/utils.ts` 148-156），而 `sandboxes` 从不含 canonical；当前的 `sessionProjectDirectory` 只读 `worktrees`，因此清单未到之前，`repo/.worktrees/feature/src` 或第二份拷贝里的会话会各自按会话目录成行——正是用户在 4–9 个项目时看到的「一个 checkout 裂成好几行」。本计划把根集合改为 `worktrees` ∪ `sandboxes` ∪ `worktree`（D-06），保持「最近的包含者」与 key 构造不变，从而在集合一致时 key 完全不变（D-07 / D-08）。契约由 `projects-groups.test.ts` 唯一拥有（D-12），热路径改动按 D-09 用 strobe 度量。

Output:
- `packages/app/src/shell/titlebar/projects-groups.ts`：根集合加宽 + `ProjectRoots` 内部类型 + `sameDirectory` 去重。
- `packages/app/src/shell/titlebar/projects-groups.test.ts`：双路径同 key、两份拷贝、更深 checkout 的回归（修复前失败）。
- `packages/app/perf/projects-groups.ts` + `projects-groups.bench.ts`：`projectGroupFor` 的 strobe 基准。
- SUMMARY 记录：修复前失败输出、strobe verdict、是否加缓存（预期：不加）。

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 服务器项目元数据（`worktree` / `sandboxes` / `worktrees`）→ 分组 | 外部输入决定哪条 checkout 行拥有一个会话目录 |
