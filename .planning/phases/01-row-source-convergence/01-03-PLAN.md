<objective>
Close the two failed truths (5 and 6) and the failed 01-02 prohibition from `01-VERIFICATION.md` by making the Projects row source a window that is actually fetched: the page asks for active roots, and the merge decides between "a page exists" and "no page yet" instead of inferring it from a row count.

Purpose: SRC-02. `inbox-sessions` omitted `archived: false`, and the server filters archive state only when the parameter is present (`packages/core/src/session/store.ts:160-161`). Archiving bumps `time_updated` to the archive moment (`packages/core/src/session/projector.ts:1000`), so archived rows concentrate at the head of the 50-row page; `parseHomeSessionIndex` then drops them after the slots are spent (`packages/app/src/home/sessions/index.ts:37-39`). When the 50 newest roots are all archived — a bulk cleanup reaches that state — the parsed page is `[]`, `floor` becomes `undefined` (`session-index.ts:22-25`), and the empty-index fallback merges every locally known root. That adds a row for an out-of-window session (truth 5, FAILED), makes the row set differ across a restart (truth 6, FAILED), and widens the window to everything the client knows — the 01-02 prohibition that `01-VERIFICATION.md` records as failed. (Truth 3, the live-archive drop, stays VERIFIED and must not regress.) Archived rows also occupy slots that an active session inside the active window would otherwise take.

Output: the `inbox-sessions` page requests `archived: false`; `mergeRootSessionIndex` takes the fetched page or `undefined` and derives its floor from the rows it can keep, so a fetched page that survives as empty means "no active roots" rather than "no page"; co-located regressions encode the all-archived page and both sides of the fallback split; the existing strobe case measures the changed merge against `origin/dev`.

Planner-settled decisions (no CONTEXT.md exists for this phase):

- **D4 — the window is a fetched page, not a row count.** The merge's first parameter becomes `readonly SessionInfo[] | undefined`. `undefined` means no page has been fetched: the known roots are the list (first paint and offline keep their rows, truth 8). Any array — including `[]` — means a page was fetched: `floor` is computed from that page and there is no known-only fallback. The empty page therefore stops being ambiguous instead of gaining a new option flag; TanStack Query already distinguishes "no data" from "an empty page", and `entries()` passes exactly that distinction through.
- **D5 — ask the server for the rows the window can use.** The `inbox-sessions` request adds `archived: false`, as every other root-session list in the app does. `parseHomeSessionIndex` stays in place (it also enforces roots-only), but it can no longer drop a row that spent a slot. This is the direct fix for the archived-rows-at-the-head state and for the hidden-active-project consequence of CR-01.
- **Floor from survivors (fixes REVIEW WR-01).** The floor is reduced over the fetched rows that survive the merge's own final filter, seeded with `Number.POSITIVE_INFINITY`. A page with no surviving root therefore yields an infinite floor that no known row can meet; a mixed page cannot lower the floor with an archived or child row.
- **Deliberate trade-off.** When the server has no active root session, Projects shows no row until the page refetches (30s stale time, `refetchOnMount`, window focus) rather than merging the known list. The alternative is the unbounded merge the phase prohibits; the post-fetch join path keeps its existing case and still holds for every non-empty window. The session created in that state is visible immediately in the Inbox view, Home and the command palette, which do not use this page.
- **Out of scope:** `IN-01` (the `includeArchived` doc comment on `session-index.ts:4`), `IN-02` (Home's duplicate archive predicate), `IN-03` (lint spacing), `IN-04` (extra benchmark cases), `IN-05` (parsing the archived page), `WR-02` (the e2e mock's archive contract) and `WR-03` (one flag selecting two behaviours) stay untouched. `INDEX_LIMIT`, query keys, `projects.tsx`, `inbox.tsx`, `home/sessions/index.ts` and `shell/commands/palette.ts` are not edited.
