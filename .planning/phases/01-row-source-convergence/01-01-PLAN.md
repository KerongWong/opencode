<objective>
Make archived sessions stop sourcing Projects rows while the Inbox view that lists archived sessions keeps them.

Purpose: SRC-01. An archived session is not active work, so it must not create or keep a project row. Every sidebar view derives rows from `mergeRootSessionIndex`, so the rule belongs there and each view declares whether it wants archived rows. Phase 3's key unification and Phase 2's worktree inventory are explicitly out of scope.

Output: `mergeRootSessionIndex` gains an `includeArchived` option (default keeps archived rows, so no existing caller changes), `createSessionInbox` passes it per view, and a new `session-index.test.ts` proves the archived-known contract plus the Projects row composition.

Planner-settled decisions (no CONTEXT.md exists for this phase):

- **D1 — archived filtering owner.** The predicate lives in the pure merge and is selected by the caller. Projects builds its inbox with `createSessionInbox()` (no `archived` option) and therefore drops archived rows; Inbox builds it with `{ archived: true }` and keeps them. Both views use the same predicate (`info.time.archived !== undefined`), so they cannot disagree.
- **D3 — API shape.** The seam is an option on `mergeRootSessionIndex`, not a change to `projects.tsx`, because `projects.tsx` already consumes `inbox.entries()`. This keeps the contract unit-testable without DOM or Solid and leaves the view layer byte-identical.
- **UI scope.** This is row sourcing only. No row markup, copy, ordering, drag, scroll, or layout changes; `projects.tsx` needs no edit.

**MVP note.** The ROADMAP Goal line is stated as an outcome, not as a user story (`As a … I want to … so that …`). This plan executes the goal as written rather than inventing a story; run `/gsd-mvp-phase 1` if the story framing must be on record.

**Flagged planner assumptions (the specless probe returned SRC-01 and SRC-03 as `unclassified`/`unresolved`, so these are authored, not confirmed):**

- SRC-01 is treated as verifiable by "the row list produced for the Projects call contains no row whose `time.archived` is set", proven by a unit test plus the manual archive check below.

- The prohibition list in frontmatter is authored from the probe and is flagged unverified; it is not a substitute for runtime confirmation.
</objective>

Facts the plan relies on (re-read each file before editing):

- `mergeRootSessionIndex(indexed, known)` puts indexed rows in a `Map`, then overwrites/inserts known rows by id, preserving an indexed row's `time.updated` when the known copy is passive, and finally filters `!info.parentID`.
- `createSessionInbox(options: { archived?: boolean })` loads the archived index only when `options.archived`, and `entries()` merges `[...activeIndex, ...(options.archived ? archivedIndex : [])]` with `data.session.known()`.
- `data.session.known` is the client's full known-session list (`runtime/server/data.ts:100`); `parseHomeSessionIndex` already drops archived rows from the fetched active index, but a locally known session can still carry `time.archived`.
- `inboxArchived(entry)` is `entry.session.time.archived !== undefined`; Inbox uses it to filter active sections and gate the archived search, while Projects never checks it.
- `docs/designs/project-grouped-sessions-sidebar.md` records the seam budget; this plan changes only `runtime/server/session-index.ts` and `shell/titlebar/inbox-model.ts` on the production side.
