# Phase 7 — 会话列表水位线 UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase changes interaction *semantics* only — batched +5 watermark replacing the binary `revealed` toggle, and the count's meaning changing to "remaining hidden". The visual form does **not** change: same bottom-of-list text button; per the 2026-11-18 user decision there is **no "Show less"** — the button only ever reads "Show N more" and disappears once the row is fully expanded (collapse is folder-fold only). Zero new design tokens. All spacing/typography/color values below are **inherited from the existing v2.1 implementation** (sidebar.tsx L549-566) and are recorded here as binding contract, not new decisions.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (increment) | `Show {{count}} more` — `count` = **remaining hidden session count below the current watermark** (changed from v2.1's "total beyond baseline 5"). Rendered only via `language.plural("sidebar.workspace.sessions.more", count)`. **No "Show less":** when the row is fully expanded the button disappears (2026-11-18 user decision); the only way back to the baseline is folding the workspace row. |
| Empty state (unchanged) | Heading: none; body: `No sessions yet` (`sidebar.workspace.sessions.empty`) |
| Error state | No new error surface. A failed row refresh keeps previously loaded sessions on screen (existing `RowSessions` contract); no watermark-specific error copy. |
| Destructive confirmation | None in this phase. |

Accessibility contract for the reveal button: it carries `aria-expanded={false}` (it only ever reveals more; there is no collapse button). No new copy keys. (`sidebar.workspace.sessions.less` becomes unused by this component and stays in the bundle.)

## UI Considerations

Applicable state considerations resolved: 7 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| zero | Watermark button | ✅ covered | Rows with ≤5 sessions render no button; exactly the 5 baseline rows show, no toggle, no count. |
| one | Watermark count | ✅ covered | 6 sessions → "Show 1 more" (plural `.one` form via `language.plural`); clicking expands all 6 and the button disappears. |
| many | Watermark progression | ✅ covered | 20 sessions: baseline 5 → "Show 15 more" → click (+5) → "Show 10 more" → click → "Show 5 more" → click (remaining ≤5 → one-step full expand) → button disappears. Count always reads remaining-hidden at the current watermark. |
| populated→boundary | ≤5 remaining | ✅ covered | When remaining hidden count ≤ 5, the next click expands **all** remaining in one step (Infinity semantics); the button then disappears. Boundary equality (exactly 5 remaining) takes the one-step path. |
| state-visibility | Attention auto-raise | ✅ covered | Sessions that are running / approval-pending / input-waiting / current within the first 50 of a row's list are visible without any click; the render-time watermark raises monotonically (never drops when such sessions finish). Unread sessions do not raise the watermark (2026-11-18 user decision). |
| reset | Watermark reset | ✅ covered | Reset to the baseline on: (a) workspace row collapse→expand (`ui.expanded` flip — baseline = max(5, attention requirement)), (b) app reload (in-memory `createStore` only — no read/write of `workspace-sidebar-ui.v1` revealed state). There is no "Show less" reset path. |
| overflow | List cap | ✅ covered | `session.list` fetches at most 50 per row; the watermark never targets beyond the fetched set, and the auto-raise ceiling (50) is naturally bounded by the fetch limit. |
